- 2026-10-13: Added incremental snapshot transfer. While recording, the watch re-serializes the
  in-progress track into a complete GPX every five minutes and transfers it with
  `{sequence, isFinal:false}`; the finalized track is sent with `isFinal:true`. Snapshots share one

  Verified: iOS tests 9 passed, watch scheme BUILD SUCCEEDED.

## Lessons Learned

- The capture layer (watch/iOS) uses `HKWorkoutSession` only for background runtime and
  discards the builder; it must never create a workout, because workout records must stay
  truthful for anyone who relies on Health/Fitness.
- Merge layer must stay device-agnostic: any GPX is valid input.
- Geotagging must happen on pre-import copies; never touch a `.photoslibrary`.
- On watchOS, do not set `CLLocationManager.allowsBackgroundLocationUpdates`; there is no
  iOS-style location background mode and it trips a CoreLocation assertion. Background
  runtime comes from the active `HKWorkoutSession` (declare `WKBackgroundModes =
  [workout-processing]`).
